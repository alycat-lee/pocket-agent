# 03 · 模块实现规格

> 本文档是 Cursor 实现代码时的接口契约。所有公开接口必须与本规格一致；内部实现可自由发挥。

## 1. `config.py` — 配置

```python
from dataclasses import dataclass

@dataclass
class AgentConfig:
    # LLM 服务
    base_url: str = "http://localhost:8080/v1"
    model: str = "local-model"          # llama.cpp server 不校验模型名
    timeout: float = 60.0

    # 采样参数
    temperature: float = 0.2
    repeat_penalty: float = 1.1
    top_p: float = 0.9
    max_tokens: int = 512               # 单次生成的最大输出 token

    # 上下文预算（字符数）
    prompt_char_budget: int = 5200      # ≈ 3500 tokens（× 1.5 换算）
    per_result_limit: int = 300         # 单条工具结果压缩后上限
    summarize_input_limit: int = 2000   # 喂给摘要器的输入上限
    use_llm_summarize: bool = False     # 默认规则截断，不开 LLM 摘要

    # 护栏
    max_steps: int = 10
    max_consecutive_intercepts: int = 2

    # 工具检索
    tool_recall_threshold: int = 8      # 注册工具数超过此值启用召回
    tool_recall_top_n: int = 5
```

## 2. `llm_client.py` — LLM 客户端

```python
from typing import Protocol, Any

class LLMClientProtocol(Protocol):
    """所有 LLM 交互的唯一抽象。测试中注入 MockLLM 实现此协议。"""

    def generate(self, prompt: str) -> str:
        """自由生成（用于 final_answer、summarize）。"""
        ...

    def generate_int(self, prompt: str, minimum: int, maximum: int) -> int:
        """约束整数生成（用于 choose_tool）。
        优先用 json_schema 约束；服务不支持时退化为正则提取 + 范围校验。"""
        ...

    def generate_json(self, prompt: str, schema: dict) -> dict:
        """约束 JSON 生成（用于 fill_args）。
        必须保证返回值符合 schema；不符合时抛 LLMFormatError。"""
        ...


class LLMFormatError(Exception):
    """约束解码失效时的兜底异常（理论上不应发生）。"""


class LlamaCppClient:
    """llama.cpp server 的 OpenAI 兼容接口封装，基于 httpx。

    - POST {base_url}/chat/completions
    - generate_int: response_format = {"type": "json_schema",
        "json_schema": {"name": "choice", "schema": {...integer...}}}
      返回 {"value": N} 结构，取 value 字段
    - generate_json: response_format 携带调用方传入的 schema
    - 所有采样参数从 AgentConfig 读取
    - 请求失败（连接错误/超时/5xx）重试 2 次后抛 LLMConnectionError
    """

class LLMConnectionError(Exception): ...
```

**实现要点**：
- llama.cpp server 的 `/v1/chat/completions` 支持 `response_format: {"type": "json_schema", "json_schema": {"name": ..., "schema": ...}}`，内部转为 grammar 约束解码
- 消息结构固定为单轮：`[{"role": "system", "content": ...}, {"role": "user", "content": ...}]`，**绝不传多轮历史**
- `generate_int` 的兜底正则：提取响应中第一个整数，校验范围，越界抛 `LLMFormatError`

## 3. `tools.py` — 工具注册

```python
from typing import Callable, Any
from dataclasses import dataclass

@dataclass
class Tool:
    name: str
    short_desc: str          # ≤ 20 字，供 choose_tool 展示
    schema: dict             # JSON Schema，从签名自动生成
    fn: Callable[..., str]   # 执行函数，返回值必须为 str（结果文本）

class ToolRegistry:
    def register(self, fn: Callable, short_desc: str | None = None) -> Tool: ...
    def get(self, name: str) -> Tool: ...
    def all(self) -> list[Tool]: ...
    def recall(self, task: str, top_n: int) -> list[Tool]:
        """关键词召回：task 与 name+short_desc 做子串/字符重叠打分，返回 top_n。
        工具总数 ≤ 阈值时直接返回全部。"""

def tool(registry: ToolRegistry, short_desc: str = ""):
    """装饰器：@tool(registry, "查询指定城市天气")
    schema 生成规则：
    - 从函数签名提取参数名与类型注解（str→string, int→integer, float→number, bool→boolean）
    - 全部参数默认 required
    - 参数描述从 docstring 的 Args 段解析（可选）
    """
```

**约束**：工具函数返回值统一为 `str`。结构化数据由工具函数自己序列化成紧凑文本。

## 4. `ledger.py` — 调用账本

import hashlib, json

    def save(self, tool_name: str, args: dict, result: str) -> None:
        """记录结果并 real_call_count += 1（仅在真实执行后调用）"""

## 5. `compressor.py` — 上下文压缩

```python
class ContextCompressor:
    def __init__(self, config: AgentConfig,
                 llm: LLMClientProtocol | None = None): ...

    def estimate_tokens(self, text: str) -> int:
        """粗估：len(text) / 1.5，向上取整"""

    def compress_result(self, result: str) -> str:
        """超过 per_result_limit 时：
        - use_llm_summarize=False：头 70% + [...截断 N 字...] + 尾 20%
        - use_llm_summarize=True：先截断到 summarize_input_limit，
          再调 llm.generate(summarize_prompt)，输出仍超限则再规则截断"""

    def build_prompt(self, *, system: str, task: str, state: str,
                     step_info: str, history: list[str]) -> str:
        """按文档 02 §3.3 的预算表拼装：
        固定区段先行，history 从最新往回塞直到 budget 耗尽。
        返回拼装后的完整 user prompt 文本。"""

    def summarize_state(self, history: list[str], keep_last: int = 3) -> str:
        """生成"已完成 N 步：<最近 keep_last 步的简要记录>"格式状态摘要，
        超过 500 字符时进一步截断中间部分。"""
```

## 6. `guard.py` — 循环护栏

```python
from dataclasses import dataclass

@dataclass
class GuardVerdict:
    should_stop: bool
    reason: str = ""          # "max_steps" | "consecutive_intercepts" | "repeat_output"

class LoopGuard:
    def __init__(self, config: AgentConfig): ...
    def on_step(self, step: int, raw_llm_output: str,
                intercepted: bool) -> GuardVerdict:
        """每步结束后调用。内部维护：
        - 连续拦截计数（非拦截步清零）
        - 上一步原始输出（比对重复）
        判定规则见文档 02 §3.5。"""
```

## 7. `prompts.py` — 提示词模板

常量集中定义，全部为 `str.format` 风格的模板字符串。内容与措辞**必须**以文档《04-运行时提示词模板》为准，实现时原样录入。

```python
SYSTEM_BASE: str          # 角色 + 硬规则
CHOOSE_TOOL: str          # 选择题模板，占位：{task} {state} {options}
FILL_ARGS: str            # 填空题模板，占位：{task} {state} {tool_name} {schema_json}

FINAL_ANSWER: str         # 最终回答模板，占位：{task} {history_text}
```

## 8. `runner.py` — 状态机执行器

```python
from dataclasses import dataclass, field
from enum import Enum

class StopReason(Enum):
    MODEL_DONE = "model_done"                 # choose 返回 -1
    MAX_STEPS = "max_steps"
    CONSECUTIVE_INTERCEPTS = "consecutive_intercepts"
    REPEAT_OUTPUT = "repeat_output"

@dataclass
class StepRecord:
    step: int
    tool_name: str
    args: dict
    result: str                # 压缩后的结果
    from_cache: bool
    error: str | None = None

@dataclass
class RunResult:
    answer: str
    steps: list[StepRecord]
    stop_reason: StopReason
    stats: dict                # total_steps / real_calls / cache_hits /
                               # intercepts / prompt_tokens_max

class AgentRunner:
    def __init__(self, config: AgentConfig, llm: LLMClientProtocol,
                 registry: ToolRegistry): ...

    def run(self, task: str) -> RunResult:
        """主循环：
        1. recall 候选工具 → build_prompt(CHOOSE_TOOL) → generate_int
        2. -1 → 跳出；否则取 Tool
        3. build_prompt(FILL_ARGS) → generate_json(schema)
        4. ledger.check → 命中：from_cache 记录；未命中：try 执行工具
           - 工具抛异常：捕获，result = f"[工具错误] {e}"，记入历史，继续循环
        5. compressor.compress_result → ledger.save → history.append
        6. guard.on_step → should_stop 则跳出
        7. 跳出后：build_prompt(FINAL_ANSWER) → generate → RunResult
        所有路径必须到达步骤 7，绝不向上抛工具异常或格式异常。
        LLMConnectionError 是唯一允许上抛的异常。
        """
```

## 9. `demo_tools.py` 与 `cli.py`

**内置演示工具**（全部 mock，返回固定/简单计算数据）：

| 工具 | 参数 | mock 行为 |
|---|---|---|
| `get_weather` | `city: str` | 内置字典返回城市天气文本（含温度）；未知城市返回"暂无数据" |
| `calculator` | `expression: str` | `ast` 安全求值四则运算，禁止 `eval` |
| `read_file` | `path: str` | 读本地文件前 2000 字；不存在返回错误文本 |
| `get_current_time` | 无 | 返回当前时间字符串 |

**CLI**（基于 `argparse`，不引入 click/typer 依赖）：

```
python cli.py demo "查询北京和上海的天气并告诉我温差"
python cli.py demo "..." --base-url http://localhost:8080/v1 --verbose
```

输出格式：每步一行日志（`[Step 1] choose=get_weather args={...} cache=miss tokens≈820`），结尾打印最终回答与汇总统计。

## 10. 测试要求

- `MockLLM`（`tests/conftest.py`）：实现 `LLMClientProtocol`，按预设队列依次返回响应，记录收到的所有 prompt
- `test_ledger.py`：指纹稳定性（参数键序不同指纹相同）、命中/未命中、计数器
- `test_compressor.py`：截断格式、预算拼装（history 逆向塞入与丢弃）、token 估算单调性
- `test_guard.py`：三种终止条件各自触发、连续拦截计数清零逻辑
- `test_tools.py`：schema 生成正确性、recall 召回排序
- `test_runner.py`：端到端剧本——
  1. 正常剧本：3 步完成任务，验证无重复真实调用
  2. 重复剧本：MockLLM 故意重复同一选择，验证账本拦截 → 连续拦截终止
  3. 失控剧本：MockLLM 永远不返回 -1，验证 max_steps 优雅终止且有最终回答
  4. 异常剧本：工具抛异常，验证循环继续且错误进入历史
- 运行命令：`pytest --cov=pocket_agent --cov-report=term-missing`
