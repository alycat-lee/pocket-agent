# Pocket-Agent 开发文档包

> 面向 8G 显存小模型（4B~9B）的工具调用 Agent 框架 —— 通过"状态机切分 + 上下文压缩 + 约束解码 + 调用去重"四大机制，让小模型达到接近大模型的工具调用稳定性。

## 项目代号

`pocket-agent`（Python 库 + CLI 演示）

## 核心理念

大模型是"一个大脑想全程"，小模型必须改成"流水线工人"：

- **不让模型做自由规划**：代码持有流程状态机，模型每次只做"单步选择题"（选工具）和"填空题"（填参数）
- **每次调用都是无状态短 Prompt**：上下文由代码按需拼装，杜绝长上下文退化导致的遗忘和重复
- **输出格式由解码层强制合法**：JSON Schema / Grammar 约束生成，不存在解析失败，也就没有失败重试
- **重复调用在框架层拦截**：调用账本记录所有调用指纹，重复请求直接返回缓存，根本不打给模型

## 如何使用这套文档驱动 Cursor 开发

1. 在 Cursor 中新建空项目目录 `pocket-agent`
2. 把 `01`、`02`、`03` 三份文档放入项目根目录的 `docs/` 下，作为 Cursor 的长期上下文（在对话中 @ 引用）
3. 打开 `05-Cursor开发提示词.md`，从 Phase 0 开始，**逐阶段**把提示词粘贴给 Cursor Composer / Agent 执行
4. 每个阶段完成后运行该阶段的验收命令，通过后再进入下一阶段
5. `04-运行时提示词模板.md` 在 Phase 5（状态机执行器）阶段用到，届时一并提供给 Cursor

## 前置环境要求

- Python 3.10+
- llama.cpp server（`llama-server`），加载 Q4_K_M 量化的小模型，推荐：
  - **Qwen3-4B-Instruct**（首选，8G 显存宽裕，KV cache 充足）
  - Qwen2.5-7B-Instruct-Q4_K_M（备选，显存较紧）
- 启动参数示例：

```bash
llama-server -m qwen3-4b-instruct-q4_k_m.gguf \
  -c 8192 --flash-attn \
  --cache-reuse 256 \
  --port 8080
```

> `-c 8192` 是关键：上下文窗口不足是本方案要解决的头号问题，服务端窗口必须够大，框架的压缩机制是在这个基础上做精细化预算管理。

## 验收总标准

用内置 CLI 演示跑一个需要 3 次以上工具调用的任务（如"查北京和上海天气并比较温差"），要求：

1. 全程无重复工具调用（账本日志无重复指纹真实执行记录）
2. 无解析失败重试（约束解码保证）
3. 单次 LLM 调用的 Prompt 不超过预算上限（日志可查）
4. 达到步数上限或循环检测触发时优雅退出，不崩溃、不死循环
