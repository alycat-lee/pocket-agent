# 10 · 问题修复与体验完善（Phase 19~22）

> 基于 github.com/alycat-lee/pocket-agent 当前代码的逐项诊断与修复方案。9 个问题按依赖关系编入 4 个 Phase，执行方式同前。

## 问题诊断总表

| # | 问题 | 根因诊断 | 修复 Phase |
| --- | --- | --- | --- |
| 1 | 连接本地模型 502 | **不是模型问题**：llama.cpp 自己永远不会返回 502。`src/llm_client/__init__.py` 的 `httpx.Client(timeout=...)` 使用默认 `trust_env=True`，Windows 系统代理环境变量（HTTP_PROXY/HTTPS_PROXY，Clash 等代理软件常设）劫持了 localhost 请求，**502 是代理服务器返回的**。curl/浏览器能通是因为它们对 localhost 有绕过规则 | 19 |
| 2 | 设置只支持单一模型 | `config_schema.py` 的模型组是扁平单实例字段（base_url/model/api_key 各一个），结构上就不支持多 provider | 20 |
| 3 | 界面风格与 DSH 不一致 | 现界面为浅色自建风格；DSH 官方为深色开发者工具风格 | 22 |
| 4 | 不支持回车发送 | 前端输入框未绑定 keydown（Enter 发送 / Shift+Enter 换行） | 22 |
| 5 | 滑动与布局缺美感 | 需整体重做，且**仓库里只有构建产物（static/assets），没有前端源码**——必须在 Phase 22 重建前端源码工程 | 22 |
| 6 | 设置缺模型测试 | 后端 `_probe_llm` 已有雏形但未暴露为 API，前端无入口 | 19 |
| 7 | 会话以 id 命名 | session 模块无 title 字段与自动命名机制 | 19 |
| 8 | 缺工作区域与权限范围 | 无 workspace 概念，read_file 无路径围栏，权限无分级 | 21 |
| 9 | 模式靠手工选择 | 模式选择器应由意图路由替代：模型自动判断走问答/工具/长文 | 20 |

## Phase 19 · 紧急修复包

````
@docs/03-模块实现规格.md @pocket-agent-docs/08-插件化架构改造.md

修复四个运行时问题，改动小、优先合入：

1. 【502 修复】src/llm_client/**init**.py 与 src/plugins/llm_deepseek.py：
httpx.Client 显式传 trust_env=False（本地 provider 必须）；
llm_deepseek 保留 trust_env=True（云端可能需要代理），
但加配置项 trust_env 可覆盖。bridge_mcp.py 的 httpx.Client
同样处理。新增测试：monkeypatch 设置 HTTP_PROXY 环境变量后，
本地 client 请求不经过代理（mock transport 断言直连）
2. 【连通性自检】把 ui_web.py 的 _probe_llm 升级为正式 API：
GET /api/health/llm → {ok, base_url, latency_ms, error}；
探测失败时 error 给出可操作文案（"连接被拒绝：llama-server
未启动" / "502：检测到系统代理拦截 localhost，
已自动直连"等分类）；前端错误引导页改用它做自动重试
3. 【会话自动命名】session 模块：SessionState 增加 title 字段，
默认 "新会话"；首轮问答完成后触发原子 LLM 调用生成标题
（新增 prompts.py 模板 SESSION_TITLE，逐字：
「为以下对话生成一个不超过 12 个字的会话标题，只输出标题本身。
用户：{user_input}」），失败回退为用户输入前 12 字截断；
emit session.renamed 事件；GET /sessions 返回 title 字段
4. 【模型测试 API】POST /api/providers/test，body {base_url,
api_key?, model?, timeout?}：先 GET /models 测连通，再发一条
max_tokens=1 的 chat completion 测生成，返回
{ok, connect_ms, generate_ms, model_list, error}；
本地地址强制 trust_env=False

验收：pytest 全绿；Windows 系统代理开启状态下 demo 不再 502；
curl POST /api/providers/test 返回延迟数据；
首轮对话后 GET /sessions 显示自动生成的标题。
````

## Phase 20 · 多模型支持与意图自动路由

````
@docs/03-模块实现规格.md @pocket-agent-docs/09-Web界面与配置外化.md

两块改造：

【多模型 providers 结构】

1. 模型配置从扁平字段重构为 providers 列表，存 settings.json：
providers: [{id, name, type: llamacpp|openai_compatible|deepseek,
base_url, api_key, model, sampling?: {temperature 等可空覆盖}}]

- default_provider_id + routing: {choose_fill: provider_id,
generate: provider_id}（原子任务与生成任务可分流）

2. llm 服务改为 ProviderRegistry：按 id 解析 client，
routing 规则决定每个原子任务走哪个 provider；
pocket.yml 的 llm-llamacpp 配置迁移为首启动时自动生成
providers[0] 的默认项
3. API：GET/POST/PUT/DELETE /api/providers、
POST /api/providers/{id}/default、PUT /api/routing；
api_key 沿用只写不读脱敏规则
4. 旧扁平配置字段自动迁移到 providers[0]，迁移后废弃，
config_schema 的模型组标记 deprecated 不再渲染

【意图自动路由（取消手工模式选择器）】

5. 新增 intent_router.py：用户输入进入 session.chat() 后先做
意图分类（规则快速路径 + LLM 兜底）：

- 规则路径：命中"写一篇/生成文章/报告"等关键词 → writer；
纯闲聊短句且无工具相关词 → qa
- LLM 兜底：generate_int 三分类（0=qa 1=agent 2=writer），
新增 prompts.py 模板 INTENT_ROUTE（逐字：
「判断用户意图类型。0=直接问答，不需要工具；
1=需要调用工具完成任务；2=需要撰写长文。
用户输入：{user_input} 只输出数字。」）
- 分类结果决定本次 run 的工具面：qa 不给工具、
agent 正常、writer 走 LongWriter

6. 模式从"用户选择"变为"系统识别"：SSE 事件 emit intent.detected
{mode, confidence}，前端显示只读徽章，用户可点击纠正
（纠正值作为当次 overrides.mode 生效并记为偏好）

验收：pytest 全绿；配置两个 provider 后路由表生效
（日志可见 choose/fill 走本地、final_answer 走云端）；
"写一篇新能源汽车分析" 自动进入 writer 流程无需手工选模式。
````

## Phase 21 · 工作区与权限范围

````
@docs/03-模块实现规格.md @pocket-agent-docs/08-插件化架构改造.md

实现 workspace 概念与权限分级：

1. workspace 服务（新插件 workspace，provides=["workspace"]）：

- 工作区列表管理（名称 + 目录路径），settings.json 持久化
- 会话创建时绑定工作区；默认 default 工作区
- API：GET/POST /api/workspaces、
PUT /api/sessions/{id}/workspace

2. 路径围栏：read_file 等文件工具的相对路径一律相对当前会话
工作区解析；resolve() 后校验绝对路径前缀在工作区内，
逃逸返回 "[工具错误] 路径超出工作区范围"；写类文件工具同理
3. 权限三档（映射审批策略，存 session 级 overrides）：

- readonly：禁用全部 cacheable=False 工具（recall 直接过滤）
- workspace：写操作弹审批（现状行为，默认）
- full：写操作免审批直接执行
权限变更 emit session.permission_changed

4. SSE 事件与 API 扩展：POST /api/chat 接受 workspace_id 与
permission 字段；GET /sessions 返回绑定的工作区名
5. 测试：路径逃逸（../ 与绝对路径攻击）全部拦截、三档权限下
写工具分别被禁用/审批/放行、会话换绑工作区后 read_file
解析到新根目录

验收：pytest 全绿；真机会话绑定工作区后 "读取 report.txt"
解析到工作区内文件，"读取 ../../etc/passwd" 被围栏拦截。
````

## 执行顺序与注意事项

1. **Phase 19 今天就能做**，四个修复互不依赖，502 修复是一行级改动（`trust_env=False`）但影响最大
2. 502 验证方法：开启系统代理的状态下跑 demo——修复前必现 502，修复后直连成功；这就是回归测试
3. Phase 20 的配置迁移要写一次性迁移逻辑：老用户的 settings.json 扁平模型字段自动转为 providers[0]，不能让已有配置失效
4. Phase 22 的前端源码工程是补债：之前只有构建产物入库，任何界面修改都无法维护。本次建立 web/ 源码目录后，static/ 产物移出版本控制
5. 意图路由的误分类是必然的（小模型能力边界），所以纠正入口（点徽章改模式）必须做——自动理解是默认路径，人工纠正是逃生通道
