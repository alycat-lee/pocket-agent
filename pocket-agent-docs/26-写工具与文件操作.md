# 26 — 写工具与文件操作（Phase 39）

> 编号接 Phase 38。差距评估第 1 条：Agent 能读不能写。本期长出"手"。

---

## 一、诊断：写工具其实已存在，但没挂载

1. `src/plugins/workspace_plugin.py` **已经实现了**带路径围栏的 `write_file`（resolve → validate_path(write=True) → 落盘），并用围栏版覆盖了 tools-core 的裸 `read_file`。
2. **但 pocket.yml 的 plugins 列表里没有 `- name: workspace`**——插件从未被装配，线上跑的还是 tools-core 里那个不设防的裸 read_file，write_file 根本不存在。
3. 所以本期第一动作是挂载（一行配置），然后是补齐 edit/list/grep 三件套 + 加固。

挂载后自动获得的既有能力（不用重复开发）：写操作 `cacheable=False` → runner 在 permission≠full 时自动走审批门（runner:412）；会话默认绑定 agent 工作区（agents/<名>/workspace）。

## 二、Phase 39 提示词（贴给 Cursor）

```text
你是一名资深 Python 工程师，继续开发 pocket-agent（本地小模型 agent 框架）。本期目标：让 agent 真正能做文件操作。红线：一切皆插件——不碰 runner/session 引擎；写操作必须走既有审批门（cacheable=False），不得另开旁路；路径围栏不得有任何逃逸口；所有新行为必须有测试。

═══ 任务 A：挂载 workspace 插件（最核心，一行配置）═══
pocket.yml 的 plugins 列表在 `- name: tools-core` 之后插入：
    - name: workspace
验证：装配后 ctx.require("tools") 里存在 write_file，且 read_file 是围栏版（路径出工作区返回错误文本而非读取成功）。写装配测试：profile=headless 全量装配后断言 write_file 已注册、read_file 已被围栏版替换（工具描述为"读取工作区内文件"）。

═══ 任务 B：write_file 加固（workspace_plugin.py）═══
1. 落盘改原子写：写 `<name>.tmp` 后 replace，避免中断留半个文件。
2. 返回值带信息量：`已写入 {len(content)} 字符：{path}`（8B 模型需要明确反馈才知道成功）。
3. 路径逃逸的报错文案改为可自纠格式：`[工具错误] 路径 {path} 超出工作区 {ws_root}，请使用工作区内相对路径`——让模型下一轮能改对。

═══ 任务 C：edit_file（str-replace 编辑）═══
workspace_plugin 新增，cacheable=False：
    def edit_file(path: str, old: str, new: str) -> str
- 同款 resolve + validate_path(write=True) 围栏；文件不存在返回错误文本。
- old 在文件中出现 0 次 → 返回 `[工具错误] 未找到匹配文本，请先用 read_file 确认原文`；出现 >1 次 → `[工具错误] 匹配到 {n} 处，请在 old 中补充更多上下文使其唯一`；恰好 1 次 → 替换并原子写，返回 `已替换：{path}（{len(old)} → {len(new)} 字符）`。
- 这三个分支文案逐字按上面写（8B 要靠报错文案自纠，不许自由发挥）。
- 测试：三分支各一例 + 路径逃逸一例 + 原子写（monkeypatch 验证 tmp+replace）。

═══ 任务 D：list_dir 与 grep_files（读类，cacheable=True）═══
workspace_plugin 新增：
1. list_dir(path: str = ".") -> str：围栏校验（读）；递归深度 ≤2；每条 `[dir] name/` 或 `[file] name {size}B`；总条数 >200 截断并附 `…（共 N 条，已截断）`；跳过 .git/node_modules/__pycache__。
2. grep_files(pattern: str, path: str = ".") -> str：regex 搜文本文件；跳过二进制、>1MB 文件与上述目录；返回 `相对路径:行号: 行内容`，每文件 ≤20 条、总 ≤100 条，超限截断注明；无效正则返回 `[工具错误] 正则无效：{原因}`。
3. 两工具描述 ≤20 字。测试：嵌套目录列举、截断、grep 命中/无命中/无效正则/跳过二进制。

═══ 任务 E：审批链路端到端验证 ═══
runner 级测试（fake LLM + fake gate）：
1. permission="workspace" 时 write_file/edit_file 触发 approval.required，gate 返回 False → 步骤被记为 approval_denied，文件未被创建。
2. gate 返回 True → 文件真实落盘且内容正确。
3. permission="full" → 不触发审批直接写。
4. 跨轮账本：同参数 write 第二轮被 ledger 拦截（cacheable=False 的既有语义），断言不被重复执行。
5. permission="readonly"：写工具不在候选列表（若现有机制是按 permission 过滤工具——若无此过滤，本期在 runner 候选裁剪处补上：readonly 时只保留 cacheable=True 工具，并加测试）。

═══ 任务 F：意图与提示词配合 ═══
1. intent_router 的 _TOOL_HINTS 补充：保存、写入、修改、创建文件、新建文件（"写"已在表中，确认"修改/保存"命中）。
2. 工具多了以后确认 recall 阈值逻辑仍生效（tool_recall_threshold），写一条 6→10 工具时召回排序的测试：任务含"保存文件"时 write_file 在召回结果中。

═══ 验收（必须全绿再交付）═══
1. pytest -q
2. grep -rn "MockLLM" src/ 无输出
3. 手测清单写进交付说明：web 端输入"在工作区创建 hello.md 内容为你好"→ 弹审批 → 允许 → agents/default/workspace/hello.md 真实存在；接着"把'你好'改成'你好世界'"→ edit_file 成功；"列出工作区文件"→ list_dir 返回；输入"读取 /etc/passwd"→ 被围栏拒绝且模型改用相对路径重试。
```
