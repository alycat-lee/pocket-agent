## 二、D3 失败根因（证据链）

`d3-two-city` 轨迹：`calculator("(查询上海天气温度)-(查询北京天气温度)")` ×3（后两次缓存命中）→ 终答"无法计算温差，缺少两地具体温度值。"，`get_weather` 零调用。

两个机制漏洞：

1. **缓存循环无拦截**：同一工具+参数的第二次缓存命中返回的还是同样的无用结果，模型第三步原样再选。CallLedger 只管去重记账，LoopGuard 只看连续拦截/重复输出，"缓存命中但无新信息"不在任何守卫视野里。
2. **领域工具缺失检查有洞**：verifier 现有"应调用工具但未调用"只在 `real_calls == 0` 触发；本题 real_calls=1（calculator），绕过了检查。任务明含"查询天气"，weather 领域工具零调用应判不合格并触发重试。

## 三、任务 A：缓存循环拦截（src/runner/__init__.py）

在 step 循环中，工具执行返回后增加一道确定性判断：

```python
# 本次调用是缓存命中，且上一步也是同一工具（无论参数），
# 说明模型在原地打转：记一次拦截，并在下一步 prompt 中注入硬提示
```

具体规则：

1. 维护 `last_tool_name`；当 `step.from_cache and step.tool_name == last_tool_name` 时：
   - `intercepts += 1`，发 `step.intercepted` 事件（reason=`cache_loop`）；
   - 把该步 result 替换为："[缓存命中，无新信息] 此调用与上一步重复。请改用其他工具或其他参数，或直接给出最终回答。"再进入下一步；
2. 该拦截照常进入 LoopGuard 的连续拦截计数，防死循环兜底不变；
3. 正常场景不误伤：不同工具的缓存命中（如先 get_weather 北京、再 get_weather 北京缓存、再 calculator）不触发——只拦"同一工具连续缓存命中"。

单测（tests/test_runner.py）：连续两次同工具缓存命中 → 第二次步的 result 含"无新信息"提示且 intercepts=1；不同工具交错缓存命中不拦截。

## 四、任务 B：领域工具缺失的 verifier 检查（src/verifier/__init__.py）

新增检查 `领域工具缺失`，条件全部满足才判：

1. `task_card.type == "agent"`；
2. `detect_tool_domains(user_input)`（复用 tools 模块的领域检测）命中 `weather` 或 `time`；
3. `verify()` 新增可选参数 `tool_names: list[str] | None`（session 调用处传 `self.last_result` 的步序列工具名）；注册表中带该 domain 的工具一个都没出现在 tool_names 里。

判定后走现有重试链，重试提示写明"任务要求查询天气/时间，但你没有调用对应工具"。

防误伤规则（必须实现，否则 D1/D9 会掉分）：

- `real_calls == 0` 时此检查不触发（已有"应调用工具但未调用"覆盖）；
- 只有 weather/time 两个直接数据领域参与，math/file/shell 不参与（算温差不一定需要 calculator）；
- qa 类型不触发。

session 侧：`verify()` 调用处从 `self.last_result.steps` 提取 `tool_name` 列表传入。

单测（tests/test_verifier.py）：agent + user_input="查询北京和上海天气告诉我温差" + tool_names=["calculator"] → 判出；tool_names=["get_weather"] → 通过；qa 类型不触发；user_input 无领域词不触发。

## 五、任务 C：终答小脏点清洗（src/session/__init__.py 或 verifier）

1. 空链接残片：终答在 `_fallback_answer` / `_attach_sources` 前过一次 `re.sub(r"\[\]\([^)]*\)", "", text)` 及 `re.sub(r"(\S)\[\]\(", r"\1（", text)` 这类最小清洗——只清 `[]()` 空链接，不动正常 Markdown 链接；
2. "缺少……文件信息"类幻觉后缀：当 agent 任务中 read_file 的工具结果为"文件不存在/未找到"且答案尾部出现"缺少.*文件"句式时，verifier 加判"幻觉文件引用"走重试。若实现复杂可降级为：仅在答案含"缺少"且 20 字内含"文件"时判出。

单测：`"项目代号是夜[](nightingale)。"` 清洗后不含 `[]()`；含"缺少天气文件信息"的答案判出；正常"北京：晴，25℃"不受影响。
