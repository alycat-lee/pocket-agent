═══ 任务 A：历史注入改硬规则（目标：D2 0.20→≥0.80，D9 0.20→≥0.60）═══
根因：session._compose_run_task 按 card.needs_history 决定是否注入历史，8B planner 常判 false（基准 d2-number/city/color 全因此丢针）。
1. 改为硬规则：只要 state.turns 非空，qa 与 agent 模式一律注入历史（滚动摘要 + 最近 keep_full_turns 轮原文），不再需要 planner 批准；needs_history 字段保留但仅作"是否做指代补全 rewrite"的依据。
2. 注入量仍受 ContextCompressor 预算约束（历史超预算时先砍旧轮、保摘要与最近轮），不能无界膨胀。
3. 测试：两轮对话（第一轮埋针"口令是7381"，第二轮问"口令是多少"），planner 返回 needs_history=false 的卡片时，断言发给 LLM 的 prompt 仍含"7381"。
4. 跑回归：python scripts/eval.py --benchmark --dims d2,d9 --tracks pocket 必须 ≥0.80 / ≥0.60 才交付。

═══ 任务 B：空回答兜底（目标：D3 0.30→≥0.50，顺带消灭线上 bug）═══

2. 测试：fake 首次空正文、二次正常 → 返回正常文本；两次都空 → 返回思维链摘要+标注。
