## 二、任务 A：内部错误与 JSON 碎片检出（src/verifier/__init__.py）

`_execution_log_leaked` 补充三类确定性模式：

1. **内部错误字符串**：答案含 `format_error`、`cannot parse int`、`invalid json`、`[工具错误]`、`[格式错误]`、`generate_int`、`generate_json` 任一即判泄漏。这些是框架内部词汇，正常终答永远不该出现；
2. **JSON 执行计划**：```json 代码块内解析出的对象/数组含 `"step"` 且含 `"tool"` 或 `"args"` 键 → 复读执行计划；
3. **结构截断**：答案含 ```json 开头但括号不配对（`{`/`[` 计数不平衡），或答案尾部 20 字内出现 `"step":` / `"args":` → 半截 JSON。

检出后走现有重试 + `_fallback_answer` 兜底链，不改 score.py。

## 三、任务 B：纯格式指令的硬校验（src/verifier/__init__.py）

新增检查 `格式违反`：当 `user_input` 含以下指令词时，对答案做对应确定性校验：

| 指令词 | 校验 |
| --- | --- |
| 只输出整数 / 只输出数字 / 只答数字 | `re.fullmatch(r"\s*-?\d+\s*", answer)`，不符即判 |
| 只输出 JSON / 只输出JSON对象 | 答案整体可 `json.loads`（允许 ```json 包裹），且不含其他文字 |
| 只回答 / 只输出（无具体格式） | 答案不超过 30 字且不含 `\n-`、`**`、编号列表 |

校验只看 `user_input`（含 rewrite 前原文），不依赖 planner constraints——planner 的 constraints 本来就经常瞎填。

检出"格式违反"后同样走重试链：重试 prompt 里把用户原话要求复述一遍。重试耗尽走 `_fallback_answer`：工具结果文本里若能 `re.search(r"-?\d+", ...)` 提取到唯一/首个数字，直接输出该数字。

反例不误判：`"北京：晴，25℃"`、`"温差是7℃。"`（user_input="只输出整数"时 `"2"` 必须通过）。
