# 12 · 意图路由感知增强（Phase 25）

> 现状诊断：意图路由代码已完整实现（`src/intent_router/` 规则+LLM 兜底、`session.py` 三分支执行、qa 空注册表机制均正常），问题是**感知层断裂**——intent 徽章渲染在 Composer（输入区），与它所描述的那条消息分离；且路由决策没有进入轨迹视图。本 Phase 只做感知增强与一处 payload 增强，不改路由逻辑。

## 问题分析

| 现象 | 根因 |
|---|---|
| 感觉不到意图判断 | 徽章在输入框区域（`Composer.tsx`），用户发完消息后注意力在消息流，徽章位置与上下文脱节 |
| qa 模式无感知 | qa 只是"不给工具"，表现与 agent 的直接回答完全相同，无任何标记区分 |
| 判断依据不可见 | `intent.detected` payload 只有 mode/confidence，没有来源（规则/LLM/纠正）与命中依据，轨迹视图无路由记录 |
| 纠正入口隐蔽 | 徽章在输入区，用户不知道它属于哪条消息、点了会怎样 |

## 修改规格

### 后端（改动小）

1. `intent_router.py`：`classify()` 返回值扩展为 `(mode, confidence, source, reason)`
   - source ∈ `rule` / `llm` / `fallback`；reason 记录命中关键词或"LLM 分类"
2. `session.py`：`intent.detected` 事件 payload 增加 `source`、`reason`、`turn` 字段；
   `force_mode` 纠正路径 source 为 `manual`
3. 轨迹事件流中，`intent.detected` 必须是每轮的第一条记录（时序保证），
   events API 落盘包含它

### 前端

4. **意图徽章迁移到消息流**：从 Composer 移除，改挂在每轮助手消息的结算行左侧
   （`自动识别：工具调用 · 规则命中 · 点击纠正`），与当轮对话强绑定
5. **qa 模式显式标记**：qa 轮的结算行显示 `直接问答 · 未调用工具`
6. **轨迹视图新增 route 记录类型**：每轮第一条记录渲染为路由决策行
   （图标 + `意图：长文写作 ← 规则命中"写一篇"`），点开检查器可见完整输入与分类结果
7. **纠正交互**：点击徽章弹出三选项（直接问答/工具调用/长文写作），
   确认后调 POST /api/chat 带 `force_mode` **重跑当轮**，并在轨迹中追加一条
   `manual` 来源的路由记录
8. Composer 顶部的模式相关 UI 全部移除（输入区只留工作区/权限选择器）

## 注意事项

1. 本 Phase 是**纯感知层改造**，路由判定逻辑一行不动——判定准不准是另一个问题（小模型三分类的准确率），那是靠 eval 任务集去量的，别混在一起改
2. 纠正重跑的实现要点：复用当轮 query_rewritten，不要重新走 rewrite——否则指代补全结果可能变化，用户会感到"纠正后答非所问"
3. 如果后续想调路由准确率：优先扩充规则关键词表（零成本、确定性），LLM 兜底只处理模糊输入；也可以在设置页把"意图路由开关"外化（config_schema 加一项），让用户能退回全 agent 模式
