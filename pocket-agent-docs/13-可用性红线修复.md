# 13 · 可用性红线修复（Phase 26）

> 针对"生成 2 万字小说"事故的定位与修复。结论先行：这不是架构问题，是四个工程细节叠加。DSH 的 Agent 核心（自由循环 + 上下文组装器 + compaction + 终端/子代理）和我们（状态机 + 原子化 + 账本/护栏）是两种路线，方向都不错——这次的失败全部发生在"模型适配与上下文注入"这一工程层。

## 事故根因分解（均可定位到代码）

| # | 根因 | 证据 | 修复 |
|---|---|---|---|
| 1 | **思考模型的思维链被当成最终回答** | `llm_client/__init__.py`：content 为空时兜底取 `reasoning_content`——思考模型（Qwen3 等）的思考过程直接成了用户看到的回复 | 修复 ① |
| 2 | **意图漏判**："生成一篇 2 万字的小说"没进 writer | `intent_router.py` 关键词表只有"写一篇/生成文章/撰写"，"生成一篇…小说"全部落空，兜底进了 agent 模式对着天气工具打转 | 修复 ② |
| 3 | **跨轮上下文污染**：无关历史（上海天气）注入创作任务 | `session.py:_compose_run_task` 把历史轮次整段注入当轮任务（needle 设计的副作用），模型被旧内容带偏 | 修复 ③ |
| 4 | **writer 不认识"2 万字"**：字数诉求完全丢失 | `writer.write(rewritten)` 未解析目标字数；且 `max_tokens=512` 单段输出天花板太低 | 修复 ④ |

## 修复规格

### ① 思考模型适配（最高优先级，不修则所有输出都可能是思维链）

- `LlamaCppClient` 请求默认携带 `chat_template_kwargs: {"enable_thinking": false}`（Qwen3 系关闭思考）；新增配置项 `reasoning_enabled: bool = False` 进 config_schema 外化
- 所有输出统一剥离 `<think>...</think>` 块（正则移除，含未闭合的残缺块）
- **删除 reasoning_content 兜底**：任何场景都不把思考过程当输出；content 为空时抛 LLMFormatError 走既有兜底路径
- 正向利用：`reasoning_enabled=true` 时把思维链通过 `step.thinking` 事件 emit——**轨迹视图检查器可以展示思考过程，消息流永远只展示最终 content**。思考过程是调试资产，不是回答

### ② 意图路由加固

- 关键词表扩充并改用正则：`(?:写|生成|创作|来)(?:一|两|几)?[篇部段个]?.{0,8}(?:小说|故事|散文|诗歌|文章|报告|文案)` 命中即 writer
- 新增**意图回归测试集** `tests/fixtures/intent_cases.json`，收录真实用户原句（含本次事故原句"给我生成一篇2万字的小说 内容随意"），每条断言期望模式；今后每次路由改动必须跑此测试集
- qa 关键词同步补：闲聊、问候、百科式提问

### ③ 上下文注入按模式分流（`_compose_run_task` 改造）

- **qa 模式**：只注入 rolling_summary，不注入逐轮原文
- **writer 模式**：只注入与用户指定素材相关的历史（默认不注入，除非用户输入含"根据/基于/接着"等承接词）
- **agent 模式**：保留注入但加硬预算（≤ session_summary_limit），且只注入压缩后的轮次摘要，不含工具步骤细节
- 原则：注入是默认关闭的特权，由模式决定开多大口子

### ④ writer 字数理解

- 进入 writer 前解析目标字数：正则 `(\d+(?:\.\d+)?)\s*万?\s*字` → `total_chars`（"2万字"=20000）；未指定用配置默认
- 分段数 = `ceil(total_chars / section_char_target)`，超出 `max_steps` 不适用（writer 有自己的循环，不受 agent 护栏限制，但设独立上限 100 段）
- writer 每段生成的 `max_tokens` 按 `section_char_target` 动态计算（中文字数 × 1.5 + 冗余），不再用全局 512
- 每段生成后校验字数下限（< 目标 60% 触发一次续写）

## 注意事项

1. ① 是红线：思维链进回答 = 产品不可用，修完后把"给我生成一篇2万字的小说"加入每次发版前的人工冒烟清单
2. 修复 ③ 可能影响 needle 测试（历史注入收紧了）——如果 needle 失败，正确做法是把用户个人信息挪进实体槽位单独注入，而不是恢复整段注入
3. 2 万字 × 小模型是长时任务（约 40 段），确认 Phase 11 的断点续跑对 writer 循环同样生效，中途失败能续
4. 这次事故的深层教训：**MockLLM 测试全绿 ≠ 真机可用**。Phase 8 的集成测试集里缺"创作类任务"用例，本次补上后，发版前真机冒烟清单至少覆盖：闲聊 / 工具调用 / 长文创作 各一条
