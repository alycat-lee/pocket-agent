# 28 — 轨迹归属与记录折叠修复（Phase 41）

> 编号接 Phase 40。两个轨迹问题，根因都已定位到代码。

---

## 一、诊断

### 问题 1：新会话轨迹混入其他会话

三层归属防线全部缺失：

1. **`run.start` 事件不带 session_id**（ui_web.py:1247 `ctx.emit("run.start", {"run_id": rid, **meta})`）→ `attach_event_persistence` 按 `payload.get("session_id") or "default"` 落盘 → **所有会话的 run.start 全部堆进 `default.jsonl`**。当用户切 agent 或会话列表为空时 sessionId 就是 "default"，轨迹视图把这个"公共垃圾抽屉"整个渲染出来——看到的就是其他会话的记录。
2. **SSE 推送不按会话过滤**：`_sse_stream._make_handler` 把总线上所有事件原样塞进队列；前端 `upsertLiveEvent`（App.tsx:300）也不校验 `data.session_id`。任何非本会话的事件（迟到事件、未来 jobs 插件的后台事件）都会直接进当前轨迹。
3. **loadTrajectory 无竞态防护**：快速切会话时，旧会话的 fetchEvents 若后返回，会覆盖新会话的空记录。

### 问题 2：task.step_done 垃圾记录

1. `_mark_plan_progress`（session/__init__.py:811）一次循环连发 N 条 `task.step_done`；writer/orchestrator 也会逐节/逐节点发。
2. 实时路径 `upsertLiveEvent`（trajectory.ts:274）会把它们折叠进任务卡，**但 projectEvents（刷新/重进会话的重建路径）没有这段折叠逻辑**——每条 step_done 落成一条 kind=other、标题就是 "task.step_done" 的裸记录。所以实时看着正常，一切换/刷新会话就冒出一排不可用记录。

## 二、Phase 41 提示词（贴给 Cursor）

```text
你是一名资深全栈工程师，继续开发 pocket-agent（本地小模型 agent 框架）。本期修轨迹归属与记录折叠。红线：不改引擎语义；事件过滤规则必须简单可测；所有新行为必须有测试。

═══ 任务 A：run.start 补归属（后端）═══
ui_web.py `_run_chat`：`ctx.emit("run.start", {"run_id": rid, "session_id": session_id, **meta})`。
全局 grep 一遍所有 ctx.emit / self._events.emit，凡 payload 能拿到 session_id 的都必须带上（逐个核对，列出清单）。测试：跑一轮会话后读 events jsonl，断言每条记录的 data.session_id 都等于当前会话（不允许出现缺失或 "default" 兜底）。

═══ 任务 B：SSE 按会话过滤（后端）═══
`_sse_stream` 增加参数 session_id；`_make_handler` 闭包内过滤：
    sid = str(payload.get("session_id") or "")
    if sid and sid != session_id:
        return  # 其他会话的事件不推送
（session_id 缺失的全局/运行级事件如 error 仍放行。）chat_post / chat_get 等所有 _sse_stream 调用点传入当前 session_id。测试：handler 收到他会话 payload 不入队；本会话与无 sid 事件正常入队。

═══ 任务 C：前端双防线 ═══
1. App.tsx handleSse 开头：
       const evSid = String(data.session_id || "");
       if (evSid && evSid !== sessionId) return;
   （注意放在 setRecords/任何状态更新之前；handleSse 依赖数组确认含 sessionId。）
2. loadTrajectory 竞态防护：新增 trajGenRef（number ref），loadTrajectory 入口 const gen = ++trajGenRef.current，await 后 `if (gen !== trajGenRef.current) return;` 再 setRecords。切会话 effect 里同时 ++trajGenRef.current 作废旧请求。

═══ 任务 D：projectEvents 折叠 task.step_done（前端核心）═══
web/src/lib/trajectory.ts projectEvents 主循环加分支（与 upsertLiveEvent:274 逻辑对齐）：
    if (ev.event === "task.step_done") {
        // 折叠进最近一条 task 记录的 plan_done，不产生独立记录
        const index = Number(data.index ?? data.step_index ?? -1);
        for (let i = out.length - 1; i >= 0; i--) {
            if (out[i].kind !== "task") continue;
            const raw = out[i].payload.plan_done;
            const planDone = Array.isArray(raw) ? raw.map(Boolean) : [];
            if (index >= 0) { while (planDone.length <= index) planDone.push(false); planDone[index] = true; }
            out[i] = { ...out[i], payload: { ...out[i].payload, plan_done: planDone } };
            break;
        }
        continue;
    }
测试：构造含 task.planned + 3 条 task.step_done 的事件序列，projectEvents 输出无 step_done 独立记录，且 task 记录 plan_done=[true,true,true]。

═══ 任务 E：回归测试 ═══
1. 后端：两个会话交替发事件，GET /api/sessions/{A}/events 只含 A 的事件；run.start 落在正确会话文件。
2. 前端：upsertLiveEvent 收到 data.session_id 非当前会话时返回原列表（在 App 层拦，组件测试模拟 handleSse 路径或抽离纯函数测试）。
3. pytest -q && cd web && pnpm test && pnpm build 全绿。
4. grep -rn "MockLLM" src/ 无输出。

═══ 交付手测清单 ═══
- 会话 A 聊两轮 → 新建会话 B 提问 → B 的轨迹只含本轮记录，无 A 的内容
- 切 agent（sessionId 变 default）→ default 会话轨迹不再堆 run.start
- 含任务卡的 run 完成后刷新页面 → 轨迹无 "task.step_done" 裸记录，任务卡步骤勾选状态正确
```
