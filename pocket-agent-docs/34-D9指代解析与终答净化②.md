## 二、失败根因（证据链）

`d9-weather-follow` 第三轮输入"这两座城市温差多少？"：

1. planner 判 `needs_history=false`（明细可见），按现有逻辑 qa 只有 `needs_history=true` 才 rewrite；
2. 即使 rewrite，qa 走 `_rewrite_if_needed(state, user_input, summary_only=True)`——摘要为空时直接返回原文。**3 轮对话未触发滚动摘要，所以指代永远得不到展开**；
3. 历史虽然硬注入进 prompt，但 8B 模型对未展开的"这两座城市" grounding 失败，输出泛泛建议，不含 needle。

结论：不是记忆丢了，是**指代解析层在摘要为空时形同虚设**，且指代类追问不该依赖小模型 planner 判断要不要 rewrite。

## 三、任务 A：指代确定性强制 rewrite（D9 0.80 → 1.00 的主修复）

### A1. 新增指代检测

在 `src/session/__init__.py`（或 planner 模块）新增：

```python
_DEICTIC_RE = re.compile(
    r"(这两|这两个|这两座|这两件|这几|那个|那个|它们|他们|她们|"
    r"它|他|她|一共|总共|之前|刚才|上面|上述|改名后|现在.*叫|"
    r"温差|相差|比较一下|比起来)"
)

def has_deictic_reference(text: str) -> bool:
    """输入含指代/汇总性词，且不是首轮时，必须 rewrite。"""
    return bool(_DEICTIC_RE.search(text or ""))
```

注意："它/他/她"单字误伤面大，只在前 2 字或紧跟标点时命中即可（可用 `(?:^|[，。,.\s])(?:它|他|她)` 收紧），单测覆盖误伤案例："它山之石"类不需要管，benchmark 不考，别过度设计。

### A2. rewrite 触发逻辑修正

`chat()` 中现有逻辑：

```python
if card.needs_history and card.type == "agent":
    rewritten = self._rewrite_if_needed(state, user_input)
elif card.needs_history and card.type == "qa":
    rewritten = self._rewrite_if_needed(state, user_input, summary_only=True)
```

改为：

```python
needs_rewrite = (
    card.needs_history
    or (state.turns and has_deictic_reference(user_input))
)
if needs_rewrite and card.type == "agent":
    rewritten = self._rewrite_if_needed(state, user_input)
elif needs_rewrite and card.type == "qa":
    rewritten = self._rewrite_if_needed(state, user_input, summary_only=True)
```

**planner 的 needs_history 只能"加"不能"减"**：规则层判定需要 rewrite 时，planner 判 false 也要 rewrite。

### A3. 修 summary_only 的空摘要死路

`_rewrite_if_needed(..., summary_only=True)` 当前：

```python
if summary_only:
    summary = state.rolling_summary.strip()
    if not summary:
        return user_input   # ← 死路：短会话永不 rewrite
```

改为：摘要为空时回退用 `_history_text(state)`（完整历史）做 rewrite：

```python
if summary_only:
    summary = state.rolling_summary.strip()
    history_text = f"摘要：{summary}" if summary else self._history_text(state)
    if not history_text.strip():
        return user_input
```

这样"这两座城市温差多少？"会被 rewrite 成"北京和上海温差多少？"，后续硬注入的历史里有具体温度，needle 命中。

### A4. 单测（tests/test_session.py 追加）

- 有历史 + "这两座城市温差多少？" → rewrite 被调用（rewrite_call_count 增加）且 rewrite prompt 中含历史原文；
- 有历史 + 无指代词 + planner needs_history=false → 不 rewrite（保护 D1/D2 现状）；
- 首轮 + 指代词 → 不 rewrite（无历史可指）；
- summary 为空但 turns 非空 → qa rewrite 用完整历史而非直接返回原文。

## 四、任务 B：QA 追问的数据落地说服（加固，防 8B 泛泛而谈）

A 修完后模型仍可能无视历史给"建议查询天气应用"。在 qa 且有历史且历史含工具数据时，给终答 prompt 加硬约束。

在 `_run_qa` 拼 prompt 处：当 `has_history` 且 run_task 含历史块时，在 prompt 尾部追加一行：

```
回答要求：只能依据对话历史中的具体信息作答；历史中有的数据必须直接使用，禁止说"通常""取决于""建议查询"这类回避性措辞；信息确实没有时才说明不知道。
```

不要新建 prompt 常量文件——直接在现有 FINAL_ANSWER_QA / 拼接逻辑里加一个 `_GROUNDING_NOTE` 常量即可。

单测：构造含天气工具结果的 2 轮历史，问指代追问，断言最终 prompt 含该约束行。

## 五、任务 C：D3 终答执行日志净化（不改评分口径）

Phase 46 报告显示 verifier 的"执行日志泄漏"检出率不足：

- `d3-weather-bj` 终答"1. 生成JSON文件：使用generate_json工具……2. 读取文件：调用read_file工具，"——典型执行计划复读 + 半截截断，`verify_reasons` 为空；
- `d3-now` 终答"（此处可能需要更多的信息，如您的位置……）"——占位符泄漏。

任务：

1. `src/verifier/__init__.py` 的 `_execution_log_leaked` 补充模式：
   - 以编号列表复述工具名：`^\s*\d+[.、]\s*.*(工具|调用|生成|读取|保存到)` 命中两行及以上；
   - 半截截断：答案末尾为 `，` `：` `：` 或以"工具，"类收尾（`re.search(r"[，,:：]\s*$", text)`）；
   - 占位符：`（此处` / `(此处` / `可能需要更多的信息`。
2. `_parrot_plan` 已有的能力复用，确认工具名出现在编号列表里也计入复读。
3. 检出后走现有重试 + `_fallback_answer` 兜底链，**不改 score.py**。

单测（tests/test_verifier.py 追加）：上述两个真实失败答案原文必须被判"执行日志泄漏"或"复读计划"；正常回答"北京：晴，25℃"不误判。
