## 二、真实残余差距

### 1. `d2-long-needle` 仍是 0 分，根因不是“历史没注入”这么简单

失败回答：

```text
未找到相关资料。

来源：
- 内部手册.md
```

这里有两个叠加问题：

1. **伪语义检索误召回**。`HashEmbedder` 只是字符 2-gram 哈希桶，`MIN_SCORE=0.15` 又太低。实测无关问题「现在项目代号是什么？只回答代号。」与《内部手册》的相似度为 **0.3928**；而真正相关的「雨巷灯火的作者」只有 **0.3689**。阈值无法同时挡住误召回和保留真召回。
2. **augment 路径让无关知识压住会话历史**。`_run_qa()` 当前拿整段 `run_task`（含历史）去检索；只要误召回资料，就切到 `FINAL_ANSWER_QA`，该提示词要求“资料不足必须答未找到相关资料”，模型于是忽略会话里的针。

另外，超过 `keep_full_turns=6` 后，埋针只能依赖 8B 模型写出的滚动摘要。把长期记忆交给小模型摘要，本身就不稳。需要一层**确定性事实钉**，不是继续调摘要提示词。

### 2. D3 的 0.90 是假性高分，严格口径应重算为 0.70

当前 `tool_used` 只看 `real_calls >= 1`，不看工具是否正确：

- `d3-two-city` 选了 `web_search`，仍得 1.0。
- `d3-three-city` 先 `format_error`，再连续选 `wiki_lookup`，仍因 `tool_used=1.0` 拿到 0.5。

按“必须调用领域工具、知识/网页工具不得顶替天气/时间工具”的严格口径重算：

| 任务 | 当前结果 | 严格口径 |
|---|---|---:|
| d3-weather-bj | get_weather，重复被账本拦截 | 1.0 |
| d3-two-city | 错选 web_search；tool_used=0、dup_call_rate=1 | 0.5 |
| d3-now | get_current_time | 1.0 |
| d3-how-weather | get_weather，重复被拦截 | 1.0 |
| d3-three-city | format_error + 错选 wiki_lookup + 重复 | 0.0 |
| **D3 严格均值** |  | **0.70** |

所以 Phase 46 不能再沿用“有工具调用即得分”的口径。先修评分，再修路由，防止框架自欺欺人。

### 3. “通过”的回答仍有明显质量污染

- `d2-name` 用户要求“只回答名字”，实际回答 `林小满\n\n来源：...`。
- `d9-pronoun` 命中了“蓝”，但正文在讨论“杯子是否为空”，且被截断。
- `d3-weather-bj` 终答复述工具步骤和缓存标记，而不是给用户结论。
- `d3-three-city` 把“模型仅输出了思考过程”的降级文本当正式回答。

这些不一定影响当前客观分，但都是用户可见缺陷。

═══ 任务 A：长期事实钉 + 检索真实性（目标：D2 0.80→1.00，D9 保持 1.00）═══

A1. 给 SessionState 增加确定性 fact_pins（长期会话事实钉），不依赖 8B 摘要：
- 仅从高置信用户原文提取，例如：
  - “请记住：项目代号是夜莺”
  - “请记住一个数字口令：7381”
  - “我叫林小满 / 我的名字是林小满”
  - “我住在成都”
  - “我最喜欢的颜色是青绿”
  - “项目后来改名为夜莺 / 项目现在叫夜莺”
- 保存规则：去重、每条 ≤80 字、只保存陈述句，不保存助手臆测。
- fact_pins 必须随 session JSON 持久化，重启后不丢。
- _compose_run_task / pack_session_history 注入优先级：fact_pins > rolling_summary > 最近轮原文；超预算时先砍旧轮，再砍摘要，不能砍 fact_pins。
- 这不是 agents 实体槽位的替代品，不要改 agents/shared 结构。

A2. 修 hash 检索误召回：
- 保留现有 sqlite 表结构，不迁移数据。
- 新增 lexical 检索模式（可把 hash 作为兼容别名）：对中文按去停用 bigram + IDF 的查询覆盖率打分，不允许再用哈希桶 cosine 当语义相似度。
- pocket.yml 的 knowledge-base 默认 embedder 改为 lexical；benchmark PocketRunner 同步使用同一模式。
- 检索阈值以测试固定：无关问题“现在项目代号是什么？只回答代号。”面对《内部手册》不得命中；相关问题“雨巷灯火的作者”必须命中《内部手册》。

A3. QA 历史优先于 augment 检索：
- _run_qa 不要用整段 run_task（含历史拼接）做检索 query；改为只检索当前 rewritten/user_input。
- knowledge_mode=augment 且已有会话历史时，会话已知信息优先；检索资料只能作为“可选补充”，必须显式告诉模型：若资料与会话问题无关，忽略资料，禁止回答“未找到相关资料”。
- knowledge_mode=strict 保持现有严格语义：资料不足仍回答“未找到相关资料”。

A4. 测试：
- 埋针“项目代号：夜莺”后插入 ≥7 轮干扰，fake 摘要故意丢失“夜莺”，最终 prompt 仍必须含“夜莺”。
- 无关知识误召回时，augment QA 不得回答“未找到相关资料”。
- lexical 检索正/反例测试。
- fact_pins 持久化测试：保存后重新 load 仍存在。

═══ 任务 B：工具领域路由 + D3 严格评分（目标：严格 D3 0.70→1.00）═══

B1. 先修 benchmark，防止错误工具得分：

  - d3-weather-bj / d3-how-weather / d3-two-city / d3-three-city：["get_weather"]

- benchmark/runners/pocket.py 的 extras 增加 tool_calls：每项含 name/args/from_cache/error。
- benchmark/score.py 的 tool_used 改为：存在 expected_tools 时，必须有真实或缓存的 expected tool 调用；命中 forbidden_tools 直接 0 分。无 expected_tools 的旧任务保持兼容。

B2. 给工具加领域元数据，不再让 8B 在全部工具里自由猜：
- Tool dataclass 增加 domain: str = "general"。
- ToolRegistry.register/register_with_disposer/@tool 支持 domain 参数，默认 general，兼容现有调用。
- 标注内置工具：
  - get_current_time：time
  - calculator：math
  - read_file/write_file/edit_file/list_dir/grep_files：file
  - get_weather（fixture）：weather

- Runner 在 choose 前做候选领域过滤：从任务文本识别 weather/time/math/file/shell/knowledge 线索；若命中直接数据领域（weather/time/file/shell/math）且未命中知识领域，则过滤掉 knowledge/web 工具。任何情况下至少保留一个候选，不得空表崩溃。

- choose_tool 的 LLMFormatError 原地重试 1 次（同 prompt + “上次未输出合法编号”提示）；第二次失败才记录 (format_error)。

B4. 测试：
