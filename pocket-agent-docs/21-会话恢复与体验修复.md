# 21 — 会话恢复、轨迹时间戳与体验修复（Phase 35）

> 对应 8 个实测问题的根因诊断与修复。编号接 Phase 34，顺序执行。

## 一、问题诊断（已逐条定位到代码）

| # | 问题现象 | 根因（代码位置） | 修复方向 |
|---|---------|----------------|---------|
| 1 | 重启后会话只剩窗口、内容丢失 | 前端切换会话时 `setMessages([])`（App.tsx:228），**从不从后端重建消息**；后端只有 `/sessions` 列表、events、export，**没有返回 turns 的会话详情 API** | 后端加 `GET /api/sessions/{sid}` 返回 turns；前端选中会话时重建消息流 |
| 2 | 新会话轮次从 4 开始 | `turnCounter` 是 useRef（App.tsx:113），`send()` 里 `turnCounter.current += 1`（:463）并注入 user.message 事件的 `turn` 字段（:488），但 **newSession 和切会话都不重置它**；trajectory.ts 的 projectEvents 以该注入值为基准，把整轮步骤归到轮次 4。后端权威轮次 `len(turns)+1` 只打在 intent.detected / task.planned 两个事件上 | 前端切会话/新会话重置 turnCounter 并按历史初始化；后端给本轮**所有**运行事件统一盖章 `turn` |
| 3 | 轨迹无步骤时间戳，无法判断事件先后 | EventStore 落盘有 `ts`（events/__init__.py），但 SSE 实时推送 `_make_handler` 只放 `{event, data}` **不带 ts**（ui_web.py:1142）；且 TrajectoryView **从不渲染** `record.ts` | SSE 推送注入服务端 `ts`；轨迹每条记录渲染 HH:MM:SS |
| 4 | 意图分析出现 undefined | planner 成功时后端发 `source="planner"`（session/__init__.py `_resolve_card`），前端 `IntentSource` 联合类型和 `SOURCE_LABEL` 都没有 planner；App.tsx 白名单把它压成 fallback（徽章没事），但 TrajectoryView:240/314 直接 `SOURCE_LABEL["planner"]` → **undefined** | 前端类型/标签/白名单补齐 `planner`（规划器），渲染处加防御兜底 |
| 5 | 测试成功不回写 model | ProvidersCard.tsx:174 仅当 `p.model` 为空才回填，且只改本地 state 不落盘；模型栏已有占位值时永远不回填 | model 为空**或不在返回的 model_list 中**即回填 model_list[0]，并立即调 updateProvider 落盘 |
| 6 | 多个本地模型无法区分 | 列表项的名称**不可内联编辑**（只有 base_url/model 输入框）；重复添加 llamacpp 预设时名字都是"本地模型" | 名称改内联输入框（随保存提交）；添加时重名自动加序号（本地模型-2） |
| 7 | 会话中无法选择 agent | agent 选择器只在 Sidebar（Sidebar.tsx:37），对话区没有 | 会话头部加 agent 选择 chip（与模型徽章并排）；仅 1 个 agent 时静态显示名称 |
| 8 | textarea 可鼠标拉伸 | styles.css:141 与 `.composer-box textarea`（:606）都是 `resize: vertical` | 全局 `textarea { resize: none; overflow-y: auto; }` |

## 二、Phase 35 提示词（贴给 Cursor）

```text
你是一名资深全栈工程师，继续开发 pocket-agent（本地小模型 agent 框架）。技术栈：后端 Python/FastAPI 插件式（src/pocket_agent/…），前端 React+TS（web/）。本次修复 8 个实测问题。红线：禁止引入 MockLLM 到 src/；不改 build 脚本；所有新行为必须有测试。

═══ 任务 A：会话详情 API（后端，修问题 1）═══
在 src/pocket_agent/plugins/ui_web.py 的 build_app 中新增：

    @app.get("/api/sessions/{session_id}")
    def api_session_detail(session_id: str, agent: str | None = Query(None)) -> JSONResponse:
        if not ctx.has("sessions"):
            return JSONResponse({"ok": False, "error": "sessions not available"}, 400)
        try:
            state = ctx.require("sessions").get_state(session_id, agent=agent or None)
        except KeyError:
            return JSONResponse({"ok": False, "error": "session not found"}, 404)
        return JSONResponse({
            "ok": True,
            "session_id": state.session_id,
            "title": state.title,
            "agent": state.agent,
            "turns": [
                {"turn": t.turn, "query_raw": t.query_raw, "answer": t.answer}
                for t in state.turns
            ],
        })

注意 get_state 若对不存在的会话是懒创建而非抛 KeyError，则先查 list_sessions 判存在性，以 list_sessions 的 (session_id, agent) 为准。给该 API 写 pytest：创建会话→跑一轮（复用现有测试的 fake LLM 设施）→断言 turns 非空且字段齐全；不存在返回 404。

═══ 任务 B：事件统一注入 ts 与 turn（后端，修问题 2/3）═══
1. ui_web.py `_sse_stream._make_handler`：推送前给 payload 盖时间戳：
       def _handler(payload: dict[str, Any]) -> None:
           payload.setdefault("ts", time.time())
           q.put({"event": event_name, "data": payload})
   （文件顶部已 import 或有 time，缺则补 import time。）
2. src/pocket_agent/runner/__init__.py：AgentRunner.run 增加可选参数 `turn: int | None = None`，并在其事件发射包装处（所有 self._events.emit 经过的入口）统一 `payload.setdefault("turn", turn)`（仅当 turn 非 None）。runner 内部保存为运行期变量，run 结束后清理，不影响并发登记。
3. src/pocket_agent/session/__init__.py：SessionManager.chat 已知 turn_no，调用 self._runner.run(...) 与 writer/orchestrator 路径时传入 `turn=turn_no`；writer 的 step.thinking 发射（_emit_think）同样带 "turn": turn_no。orchestrator/worker/merger 事件若在 orchestrator 模块发射，同样从 chat 把 turn_no 传下去盖章；做不到全链路则至少保证 runner/writer 路径。
4. 这样 step.start / step.tool_call / step.thinking / answer.done 等全部携带权威 turn，前端不再自己猜。写测试：fake LLM 跑 2 步工具调用，断言收集到的每个 step.* 事件都含 turn == 1。

═══ 任务 C：前端会话重建与轮次重置（修问题 1/2）═══
web/src：
1. api/client.ts 新增 fetchSessionDetail(sid, agent?) 调 GET /api/sessions/{sid}。
2. api/types.ts 加 SessionDetail 类型。
3. App.tsx：
   - 切会话的 useEffect（现 setMessages([]) 处）改为：先 setMessages([])，然后 fetchSessionDetail 成功时把 turns 重建为消息流——每轮产生 user 消息（content=query_raw）与 assistant 消息（content=answer，turnId=`turn-${t.turn}`），并按顺序 setMessages；同时 `turnCounter.current = turns.length`（无 turns 则 0）。失败/404 保持空。
   - newSession() 内补 `turnCounter.current = 0`。
   - 切会话 effect 内同样 `turnCounter.current = 0`（重建完成后会被历史长度覆盖）。
   - 会话头部标题 `{sessionId}` 改为显示当前会话 title（sessions 列表里查找，找不到回退 sessionId）。
4. 重建的消息不带 settlement/intent（历史未存这两个字段），属预期，不要伪造。

═══ 任务 D：轨迹渲染时间戳（修问题 3）═══
web/src/components/TrajectoryView.tsx：每条记录行内渲染时间，格式 HH:MM:SS（record.ts 为秒级 Unix 时间戳，转本地时区；ts 为 null 时不渲染占位）。样式用既有 status-meta 或新建 .rec-ts（等宽数字、12px、弱化色），放在记录标题右侧。加/改组件测试：给定 ts 的记录渲染出匹配 /\d{2}:\d{2}:\d{2}/ 的文本。

═══ 任务 E：意图来源补 planner（修问题 4）═══
1. web/src/api/types.ts：IntentSource 改为 "rule" | "llm" | "fallback" | "manual" | "planner"。
2. web/src/lib/intent.ts：SOURCE_LABEL 加 planner: "规划器生成"；sourcePhrase 无需改（planner 带 reason"任务卡"会走 reason 分支）。
3. App.tsx:394 附近白名单 ["rule","llm","fallback","manual"] 加 "planner"。
4. 防御兜底：TrajectoryView.tsx 中所有 SOURCE_LABEL[x] / MODE_LABEL[x] 渲染处改为 `SOURCE_LABEL[x] ?? String(x ?? "")`、`MODE_LABEL[x] ?? String(x ?? "")`，杜绝任何未来新值再出 undefined。
5. 组件测试：source=planner 的 route 记录渲染"任务卡"且全文不含 "undefined"。

═══ 任务 F：Providers 测试回写与名称（修问题 5/6）═══
web/src/components/ProvidersCard.tsx：
1. 测试成功后的回填条件从 `!p.model.trim()` 改为：`!p.model.trim() || !res.model_list.includes(p.model)`。回填后立即自动调 updateProvider 落盘（带当前 name/base_url/model=回填值/api_key 脱敏处理沿用现有逻辑），setStatus 提示"已回填并保存模型 xxx"。回填失败静默降级为仅本地回填并提示需手动保存。
2. 每个 provider 项的 header 名称 `<strong>{p.name}</strong>` 旁（或替换为）加内联文本输入框，默认值 p.name，随"保存"按钮一起提交 name 字段（updateProvider 已支持 name）。
3. 添加 provider 时若 draftName 与现有 provider 重名，自动追加序号：本地模型 → 本地模型-2、-3…（在前端 createProvider 前处理）。
4. 组件测试：模拟 testProvider 返回 model_list=["qwen3-8b-q4"]，model 栏已有 "local-model"，点击测试后断言 model 输入框值变为 "qwen3-8b-q4" 且 updateProvider 被调用。

═══ 任务 G：会话头部 agent 选择（修问题 7）═══
```
