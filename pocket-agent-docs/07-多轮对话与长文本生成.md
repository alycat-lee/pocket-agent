# 07 · 多轮对话与长文本生成（Phase 10~12）

> 前置条件：Phase 0~9 完成。本文档为 pocket-agent 增加三个新模块：会话层（session.py）、断点续跑（checkpoint.py）、长文本生成器（writer.py）。执行方式同前：逐阶段粘贴给 Cursor，验收通过再进下一阶段。

## 新增模块规格

### 1. session.py — 会话层

```python
@dataclass
class TurnRecord:
    turn: int
    query_raw: str          # 用户原始输入
    query_rewritten: str    # 指代补全后的完整问题
    answer: str

@dataclass
class SessionState:
    session_id: str
    turns: list[TurnRecord]           # 仅保留最近 keep_full_turns 轮完整记录
    rolling_summary: str              # 更早轮次的滚动摘要，≤ 500 字符
    write_op_ledger: CallLedger       # 跨轮持久：仅记录 cacheable=False 的工具

class SessionManager:
    def __init__(self, config: AgentConfig, llm: LLMClientProtocol,
                 runner: AgentRunner): ...

    def chat(self, session_id: str, user_input: str) -> str:
        """1. 若该 session 已有历史：调 REWRITE_QUERY 做指代补全，
           输出完整独立问题；首轮跳过 rewrite
        2. 构造当轮上下文：rolling_summary + 最近完整轮次
        3. 调 runner.run(rewritten_query)，当轮使用新建 CallLedger
           （读类缓存仅当轮有效）；cacheable=False 工具的拦截记录
           同步进 write_op_ledger 跨轮生效
        4. 轮次结束：追加 TurnRecord，丢弃当轮 StepRecord 细节
        5. turns 超过 keep_full_turns（默认 6）时，最老的一轮
           经 ROLLING_SUMMARY 压缩并入 rolling_summary"""
```

设计铁律：
- 轮次边界 = 记忆压缩点：工具调用细节绝不跨轮存活
- 跨会话隔离：SessionState 之间零共享，测试必须覆盖

### 2. checkpoint.py — 断点续跑

```python
class CheckpointStore:
    """JSON 落盘到 .checkpoints/{run_id}.json"""
    def save(self, run_id: str, state: dict) -> None: ...
    def load(self, run_id: str) -> dict | None: ...
    def clear(self, run_id: str) -> None: ...

# AgentRunner 变更：
def run(self, task: str, run_id: str | None = None) -> RunResult:
    """run_id 非空时启用断点续跑：
    - 每步结束后 dump {history, ledger_records, step_index}
    - 启动时检测到已有 checkpoint：恢复 history 与 ledger，
      从断点步继续，已执行步骤的工具调用全部走账本缓存不重复执行
    - 正常完成后 clear(run_id)"""
```

### 3. writer.py — 长文本生成器

```python
@dataclass
class SectionSpec:
    title: str
    points: list[str]        # 本段要点
    target_chars: int

@dataclass
class ConsistencyCard:
    facts: list[str]         # 人名/数字/术语/立场，序列化后 ≤ 300 字符

class LongWriter:
    def __init__(self, config: AgentConfig, llm: LLMClientProtocol): ...

    def write(self, topic: str, total_chars: int,
              material: str = "") -> str:
        """四段式流水线，每步都是独立原子调用：
        ① generate_json(OUTLINE 提示词, outline_schema) → list[SectionSpec]
           解析失败兜底：按 total_chars/500 均匀切分、无要点
        ② 一致性卡：material 非空时用规则提取（含数字的句子 +
           首行术语），material 为空时由 OUTLINE 步骤顺带产出
        ③ 逐段 generate(SECTION_WRITE)：输入 = 大纲全文 + 本段要点 +
           一致性卡 + 前段结尾 seam_tail_chars（默认 250）字
        ④ 拼接去重：检测段首与前段结尾的重叠句并裁掉，
           重叠窗口上限 overlap_max（默认 80）字"""

class WriterMetrics:
    """自动连贯性指标，供测试与评测调用"""
    def ngram_overlap(self, text_a: str, text_b: str, n: int = 3) -> float: ...
    def numeric_consistency(self, full_text: str) -> list[str]:
        """抽取全文数字，返回同一指标多处出现但取值不一致的冲突列表"""
    def outline_coverage(self, outline: list[SectionSpec],
                         full_text: str) -> float: ...
```

### 4. AgentConfig 新增配置项

```python
# 会话
keep_full_turns: int = 6            # 保留完整记录的轮数
session_summary_limit: int = 500    # 滚动摘要字符上限

# 长文本
section_char_target: int = 500      # 每段目标字数
seam_tail_chars: int = 250          # 接缝上下文长度
overlap_max: int = 80               # 拼接去重的最大重叠窗口
```

## 新增运行时提示词（录入 prompts.py，逐字使用）

REWRITE_QUERY：

```
根据对话历史，把用户的最新输入改写成一个完整、独立的问题。
不要回答，只输出改写后的问题。

对话历史：
{history_text}

最新输入：{user_input}

改写后的问题：
```

ROLLING_SUMMARY：

```
把这段对话历史压缩为不超过 {limit} 字的摘要，
保留所有关键事实（数字、名称、用户提供的个人信息）：

{turns_text}

只输出摘要本身。
```

OUTLINE：

```
为主题「{topic}」生成一篇约 {total_chars} 字文章的大纲。
每段给出标题和 2~3 个要点，每段约 {section_chars} 字。
参考材料：{material}

只输出 JSON。
```

outline_schema：`{"type":"object","properties":{"sections":{"type":"array","items":{"type":"object","properties":{"title":{"type":"string"},"points":{"type":"array","items":{"type":"string"}}},"required":["title","points"]}}},"required":["sections"]}`

SECTION_WRITE：

```
你正在逐段撰写文章「{topic}」。
全文大纲：{outline_text}
必须保持一致的事实：{consistency_text}

请撰写第 {index} 段「{section_title}」，要点：{points}
要求：约 {target_chars} 字；承接上文，不要重复前文已写内容。

上文结尾：{seam_text}

只输出本段正文。
```

## 执行顺序与注意事项

1. 顺序：Phase 10 → 11 → 12。10 和 11 无依赖可并行让两个对话做，但 runner.py 都有改动，建议还是串行避免冲突
2. Phase 10 的 needle 用例是多轮能力的试金石：小模型摘要必然丢信息，如果 A7749 丢了，先检查 ROLLING_SUMMARY 的摘要上限是否太小，再考虑把用户个人信息单独结构化存储（实体槽位），这是已知的后续优化方向
3. Phase 12 的三个指标里，**数字一致性冲突为 0 是硬指标**（一致性卡在起作用），重叠率和覆盖率允许小幅波动
4. 接缝流畅度的最终评判靠人眼抽检，自动指标只负责筛掉灾难性输出
