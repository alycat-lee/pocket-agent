# 11 · 遗留问题修复（Phase 23~24）

> 针对最新提交（97248e6）代码检查后的逐项诊断。先讲一个前置根因，再排两个修复 Phase。

## 0. 前置根因：你跑的很可能是旧构建产物

代码检查发现：回车发送（`Composer.tsx:94`）、模型组 deprecated 过滤（`SettingsPage.tsx:52`）**在源码里都已经实现了**，但界面上问题依旧——原因是：

- `.gitignore` 已把 `src/plugins/static/`（构建产物）全部排除，vite 构建输出到该目录
- 拉取新代码后如果没有重新执行 `cd web && pnpm build`，后端服务的还是**本地旧构建**

所以 Phase 23 第一件事就是加**构建版本校验**，让"产物过期"自己报警，不再靠人肉记得构建。

## 1. 逐项诊断

| # | 问题 | 诊断结论 |
|---|---|---|
| 1 | 颜色风格还是深色 | **我的设计给错了**：DSH 官方 Web GUI 实际是浅色主题（官方设置弹窗为白色卡片 + 浅灰底 + DeepSeek 蓝强调色）。`styles.css` 的深色令牌（#0d1117/#161b22）需整体替换为浅色设计令牌 |
| 2 | 设置里两个"模型"菜单 | 后端 schema 已标 deprecated、前端源码也有过滤——但需双保险：后端应直接从 API 响应里剔除 deprecated 项，前端导航按名称去重。旧构建也会表现为双菜单（见 §0） |
| 3 | 新建会话显示 id、历史不保存 | 两处真问题：① 前端 `App.tsx:491` 新建会话时硬编码 `title: id`，且**没有监听 `session.renamed` 事件**（后端自动命名已实现，事件没人接收）；② `SessionManager` 纯内存态，无落盘，重启即丢 |
| 4 | 轨迹互相遮盖、无法滑动 | 根因明确：`VirtualList.tsx` 用**固定行高 + 绝对定位**（`top: index * rowHeight`），而记录实际高度不一（轮次头/普通记录/错误文本高度都不同），内容超过固定行高就叠在一起。且缺少"默认锚定底部"逻辑 |

轨迹视图对齐 DSH 的官方行为（逐条照做）：
- **默认打开定位到最新（底部）**，向上滚动加载更早记录
- 流式期间跟随尾部；用户上滚即暂停跟随，回到底部恢复
- 进行中的记录只显示开始标记，不虚构耗时

## Phase 23 · 构建校验与会话持久化（后端/工程）

````
@docs/03-模块实现规格.md @pocket-agent-docs/08-插件化架构改造.md

三项工程修复：

1. 【构建版本校验】web/vite.config.ts 构建时生成
   build-info.json（{version: git short hash 或时间戳}）打进产物；
   ui-web 插件启动时读取它并打印版本；GET /api/health 增加
   ui_build 字段；构建产物缺失或版本早于后端源码时，
   启动日志显著警告"前端产物过期，请执行 cd web && pnpm build"
2. 【会话持久化】SessionManager：每轮结束后将会话落盘到
   .sessions/{session_id}.json（title、turns、rolling_summary、
   created_at、updated_at），启动时扫描加载；写入用临时文件 +
   rename 原子操作；list_sessions 按 updated_at 降序返回
   （含 title）；新增 DELETE /api/sessions/{id}
3. 【schema 剔除废弃项】GET /api/config/schema 直接不返回
   deprecated: true 的条目（不只靠前端过滤）；
   对应测试：响应中不存在任何 deprecated 项

测试：会话持久化（写盘后重建 SessionManager 能恢复 title 与
turns）、损坏的 session 文件跳过不崩溃、schema 无 deprecated 项。

验收：pytest 全绿；重启服务后 GET /sessions 仍列出历史会话及标题。
````

## Phase 24 · 前端修复包（使用 skill）

````
@pocket-agent-docs/09-Web界面与配置外化.md @pocket-agent-docs/11-遗留问题修复.md

修复四个界面问题。完成后必须执行 cd web && pnpm build，
并用浏览器实际验证（不许只改源码不构建）。

1. 首先调用 /ui-ux-pro-max skill。视觉方向：DSH 官方 Web GUI
   是浅色主题（白色卡片 + 浅灰页面底 + DeepSeek 蓝强调色），
   把 styles.css 的设计令牌整体替换为浅色体系：
   --color-background: #f7f8fa；卡片与侧边栏 #ffffff；
   边框 #e5e7eb；主文字 #1f2329；次要文字 #6b7280；
   强调色 #4d6bfe；徽章用语义色浅底（绿/黄/红）；
   圆角 8~10px、细边框、克制轻阴影；数字与延迟用等宽字体。
   深色令牌全部删除，不留暗色残留
2. 【双模型菜单】设置页导航按显示名去重；schema 已不返回
   废弃组，硬编码"模型"项排首位；任何情况下不允许出现
   两个同名菜单项（加组件测试断言）
3. 【会话命名联动】新建会话调 POST 后列表项标题显示"新会话"；
   订阅 SSE 的 session.renamed 事件原地更新列表标题；
   首轮 answer.done 后主动 refetch 会话列表兜底；
   会话列表支持删除（DELETE /api/sessions/{id}）
4. 【轨迹视图重写】废除固定行高虚拟滚动（记录量级小，不需要），
   改为普通流式布局：.traj-list 容器 overflow-y: auto +
   flex column；挂载与切到轨迹标签时 scrollTop = scrollHeight
   锚定底部（最新在底部）；流式期间跟随尾部，
   用户上滚超过 80px 暂停跟随后显示"回到底部"浮钮；
   顶部"加载更早"按钮（sticky）；记录高度由内容自适应，
   互相遮盖问题必须消失；轮次头与记录的层级样式对齐 DSH 风格
5. 全部完成后调用 /impeccable skill 审查，修正 blocker 再交付

验收：pnpm build 后浏览器实测——界面为浅色主题；
设置页只有一个模型菜单；新建会话显示"新会话"且首轮后自动改名；
重启服务历史会话仍在；轨迹视图默认停在最新记录、
可上滚加载更早、无遮盖无重叠；/impeccable 无 blocker。
````

## 执行顺序与注意事项

1. 先 Phase 23 后 Phase 24；23 的会话持久化是 24 前端联动的数据源
2. **每次前端改动后必须 `cd web && pnpm build` 再刷新浏览器验证**——本轮 4 个问题里至少 2 个是"源码已修、产物未更新"造成的假性遗留
3. 主题误判的教训：涉及"对齐某产品风格"的需求，先拿到官方界面截图确认再写设计令牌。DSH 官方 Web GUI 是浅色（其 TUI 是深色终端风格，两者别混淆）
4. 轨迹视图以后若记录量大需要虚拟滚动，必须用 ResizeObserver 实测行高，禁止再回到固定行高 + 绝对定位的写法
