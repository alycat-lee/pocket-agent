# 04 · 运行时提示词模板库

> 本文件定义框架**运行时喂给小模型**的全部提示词。实现时录入 `prompts.py`，措辞原样使用，不要改写——每一处措辞都针对小模型的理解能力做过取舍。

## 设计原则

1. **短**：每个模板主体 ≤ 150 字，小模型对长指令的遵循率随长度断崖式下跌
2. **指令放在最后**：小模型对 Prompt 末尾的指令注意力最强，关键输出要求永远压轴
3. **输出格式用示例锁死**：与其描述格式，不如给一行示例
4. **硬规则显式声明**："不要重复调用"写进 system，虽然框架层有兜底，模型层先拦一道
5. **零示例依赖**：不依赖 few-shot（占预算），靠约束解码保证格式

## SYSTEM_BASE

```
你是一个任务执行助手，通过调用工具逐步完成任务。

规则：
1. 每一步只做一件事
2. 不要重复调用同一个工具和相同的参数，已有结果直接使用
3. 严格按照要求的格式输出，不要输出任何解释
```

**说明**：规则 2 是模型层的防重复声明；规则 3 压制小模型常见的"输出格式 + 解释废话"毛病。

## CHOOSE_TOOL（选择题）

```
任务：{task}

当前进度：{state}

已执行的历史（最近的在前）：
{history_text}

可用工具：
{options}

下一步应该使用哪个工具？如果已有信息足以回答任务，输出 -1。
只输出一个数字。例如：0
```

**占位符**：
- `{options}` 格式：`0. get_weather: 查询指定城市天气\n1. calculator: 计算数学表达式`（编号 + 名称 + 短描述，**不含 schema**——schema 只在 fill_args 步骤出现，这是省预算的关键）
- `{history_text}`：压缩后的历史，为空时填 `（无）`

**说明**：
- "已执行的历史"明确列出，让模型一眼看到自己干过什么——这是对抗遗忘最直接的提示手段
- 输出约束为整数（json_schema: `{"type": "object", "properties": {"value": {"type": "integer", "minimum": -1, "maximum": N}}, "required": ["value"]}`）

## FILL_ARGS（填空题）

```
任务：{task}

已知信息：{state}

请为工具 {tool_name} 生成调用参数。
参数要求：{schema_json}

只输出 JSON 对象，不要输出任何其他内容。
```

**说明**：
- 此步骤用 `response_format` 携带工具的真实 JSON Schema 做约束解码，Prompt 中的 `{schema_json}` 是 schema 的紧凑序列化（separators=(",", ":")），双保险
- 不给格式示例——schema 本身就是最精确的示例，多余的示例反而诱导模型照抄示例值

## SUMMARIZE（可选，结果摘要）

```
将以下内容压缩为不超过 {limit} 字的摘要，保留所有关键数据（数字、名称、结论）：

{text}

只输出摘要本身。
```

**说明**：仅 `use_llm_summarize=True` 时使用。`{text}` 已被规则截断到 2000 字以内。"保留关键数据"是防小模型摘要时丢数字的关键指令。

## FINAL_ANSWER

```
任务：{task}

以下是通过工具调用收集到的信息：
{history_text}

基于以上信息回答任务。如果信息不足以完整回答，说明缺失的部分。
直接输出回答，不要复述过程。
```

**说明**：
- "信息不足时说明缺失部分"保证护栏终止路径下回答仍然诚实可用
- "不要复述过程"压制小模型把历史记录抄一遍的倾向（重复输出的常见形态）

## 防重复设计在提示词层的落点汇总

| 机制 | 落点 |
|---|---|
| 硬规则声明 | SYSTEM_BASE 规则 2 |
| 已执行历史可见 | CHOOSE_TOOL 的 {history_text} 区段 |
| 输出空间压缩 | CHOOSE_TOOL 整数编号 + 约束解码 |
| 格式零解释 | 所有模板的"只输出…"指令 |
| 复述压制 | FINAL_ANSWER 的"不要复述过程" |

提示词层是第一道防线，框架层（账本、护栏、约束解码）是确定性保障——两层缺一不可，但**永远不要指望提示词层单独生效**。
