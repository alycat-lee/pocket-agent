## 二、设计结论

Phase 49 的"领域工具缺失"检查**方向对、位置错**。后置检查只能贴标签，不能改行为。闸门必须前移到 run 收尾前：模型想结束时，缺工具就不让它结束。

## 三、任务 A：收尾前领域闸门（src/runner/__init__.py，主修复）

在 step 循环中，模型选择 `-1`（结束作答）的分支处插入确定性闸门：

```python
if choice == -1:
    missing = self._missing_domain_tools(task, steps, candidates)
    if missing and not domain_gate_fired:
        domain_gate_fired = True
        intercepts += 1
        self._emit("step.intercepted", {"reason": "domain_gate", ...})
        steps.append(StepRecord(
            step=step, tool_name="(domain_gate)", args={},
            result=f"[未完成] 任务要求查询{missing}，但你还没有调用对应工具。"
                   f"下一步必须选择{missing}工具，获取真实数据后才能作答。",
            from_cache=False, error=None,
        ))
        continue  # 不让它收尾，带着提示重新 choose
```

要点：

1. `_missing_domain_tools(task, steps, candidates)`：复用 `detect_tool_domains(task)`，命中 weather/time 且 steps 里没有任何该 domain 工具（用 `tool_name_domain` 判断，注意跳过 `(format_error)`/`(domain_gate)` 伪步），且当前候选池里存在该 domain 工具（不在池里说明配置如此，不强求）→ 返回中文标签如"天气"；否则返回 None；
2. **只强制一次**（`domain_gate_fired` 旗标）：强制后模型仍不调用就放行收尾，由 verifier 后置检查兜底，防死循环；
3. 闸门提示里不要列编号（候选顺序每步可能变），只点名工具类型，让 choose 正常走；
4. 闸门伪步计入 intercepts，进 LoopGuard 连续拦截计数，与既有防护兼容。

单测（tests/test_runner.py）：

- 天气任务模型首轮选 -1 且未调 get_weather → 出现 `(domain_gate)` 步且 run 继续；
- 闸门触发一次后模型再选 -1 → 正常收尾（不二次强制）；
- 已调 get_weather 后选 -1 → 无闸门步；
- 非领域任务选 -1 → 无闸门步。

## 四、任务 B：read_file 幻觉路径的防线（plugins/workspace 或 file 工具实现）

d3-how-weather 的 6 次 read_file 全部打向不存在的路径，但明细里 `error: null`——工具把"文件不存在"当正常文本返回了，模型和观测层都分不清成败。

1. 找到 read_file 工具实现，确认文件不存在时的返回：**result 必须以"文件不存在"开头**，且 runner 记录该步时 `error` 字段置为相同文本（让下游 fallback / verifier 可判定失败步）；
2. 同一 run 内 read_file 连续 2 步返回"文件不存在"时，在该步 result 尾部追加提示："该路径不存在。请确认文件路径，或改用其他工具获取数据。"——不改行为只加提示，防模型继续换着文件名瞎试；
3. 不限制路径白名单（workspace 权限是另一条线，本期不动）。

单测：不存在路径 → error 非空且含"文件不存在"；连续两次不存在 → 第二次 result 含换工具提示。

## 五、任务 C：收尾后降级尾巴的位置修正（src/verifier 或 session）

后置"领域工具缺失"兜底保留，但 `attach_degrade` 的"该回答未通过验收：……"尾巴目前直接拼在用户可见答案后。改为：降级原因只进事件（`answer.rejected` 已有）和 trajectory，**不上屏**；用户可见的答案若因缺工具数据而不可信，替换为诚实说明："未能获取实时数据（未调用{label}工具），以上回答不保证准确。"——由代码拼装，不依赖模型。

单测：verify 失败耗尽重试后，最终答案不含"该回答未通过验收"，含诚实说明；事件流里仍有 answer.rejected 记录。
