# 23 — 会话流式输出（Phase 37）

> 编号接 Phase 36。目标：对标 DSH/豆包的逐字输出体验，回答边生成边显示；同时不破坏状态机回路的约束解码与验收机制。

---

## 一、诊断

当前全程无流式：

1. `OpenAICompatClient._request_with_retry`（llm_client/__init__.py:247）虽然用了 `client.stream("POST", ...)`，但紧接着 `response.read()` **一次性读全量**，请求体也没传 `stream: true`——只是用了流式传输的 API 形态，语义上还是等整段生成完。
2. 所有面向用户的文本（qa 回答 session:627、验收重试 session:690、agent 最终回答 runner:511、长文分节 writer:277）都走 `generate()` 阻塞返回，SSE 只在最后推 `answer.done`，前端一次性上屏。
3. 因此长回答期间界面"卡住"，停止按钮虽能中断（abort_current 关连接），但用户看不到已生成的部分。

**设计约束（不能破坏的底线）**：
- `generate_int` / `generate_json`（选工具、填参）**保持非流式**——约束解码必须拿到完整 JSON，流式无意义。
- summarize / rewrite 等内部调用不流式。
- 流式只用于"面向用户的最终文本"。
- `answer.delta` 增量事件**只推 SSE，不落盘**（否则 events jsonl 被刷爆）；`answer.done` 仍携带完整终稿，轨迹重建不受影响。
- 验收驳回重试时，重试的新增量要**替换**而非追加旧气泡。
